# 架构总览

## 应用划分

### apps/cli

- 入口：`apps/cli/main.go`
- 模块：`apps/cli/checker`、`apps/cli/scheduler`、`apps/cli/recorder`、`apps/cli/config`

### apps/gui

- 后端入口：`apps/gui/main.go`
- 应用桥接：`apps/gui/app.go`
- 核心模块：`apps/gui/pkg/*`
- 前端：`apps/gui/frontend/src/*`

## GUI 主链路

1. GUI 为每个启用监听的主播启动独立 worker。
2. Worker 自己检查开播状态、解析直播地址并启动 FFmpeg。
3. Worker 通过结构化事件向 GUI 回报状态、日志和录制结果。
4. GUI 通过 Wails 事件更新前端，并将结果写入 `history.json`。

Windows GUI 默认通过当前主程序的内置 `--worker` 模式启动 worker，因此发布
GUI 时不需要额外附带 `recorder-worker.exe`。CLI 和服务器部署仍可单独构建
`recorder-worker`。

## 鉴权模型

- `auto`：OAuth + Cookie 自动协同
- `oauth`：仅 OAuth API
- `cookie`：仅 Cookie 会话

## 并发模型

- 每主播拥有独立 worker 与 FFmpeg 进程。
- 单路录制异常不会阻塞其他主播或 GUI。
- 删除、暂停和正常退出会清理对应 worker 与 FFmpeg。
