# 数据目录与发布结构

本项目建议把“源码、程序、运行数据”分清楚。这样开源、打包、迁移机器时都不容易乱。

## 源码目录

仓库里应该保留：

```text
apps/
deploy/
docs/
scripts/
README.md
go.work
go.work.sum
```

仓库里不应该提交：

```text
config.yaml
cookies.txt
history.json
download/
logs/
*.exe
node_modules/
dist/
build/bin/
.gocache*/
```

这些文件要么是个人配置，要么是构建产物，要么是录制结果。

## 便携模式

适合自己使用、U 盘使用、压缩包发布。

```text
TwitCastingRecorder/
  twitcasting-recorder-gui.exe
  twitcasting-recorder.exe
  recorder-worker.exe
  config.yaml
  cookies.txt
  history.json
  download/
  logs/
```

优点是搬家简单，整个文件夹复制走就行。缺点是打包新版时要注意别覆盖自己的 `config.yaml` 和 `cookies.txt`。

## 安装模式

适合未来做安装包。

```text
Program Files/
  TwitCastingRecorder/
    twitcasting-recorder-gui.exe
    twitcasting-recorder.exe
    recorder-worker.exe

AppData/
  TwitCastingRecorder/
    config.yaml
    cookies.txt
    history.json
    download/
    logs/
```

优点是程序和数据分离，升级更安全。缺点是初期实现更复杂，需要在 GUI 和 CLI 里明确用户数据目录。

## 当前建议

现阶段推荐继续使用便携模式，但发布包应做到：

```text
release/
  twitcasting-recorder-gui.exe
  twitcasting-recorder.exe
  recorder-worker.exe
  config.example.yaml
  README.txt
```

第一次启动时由用户复制或生成 `config.yaml`。不要把开发机上的 `config.yaml`、`cookies.txt`、`history.json` 放进公开 release。

## 配置文件策略

`apps/gui/config.example.yaml` 和 `apps/cli/config.example.yaml` 是公开示例。

`config.yaml` 是用户私有文件，可能包含：

- OAuth client 信息
- OAuth access token
- Cookie 路径
- 代理地址
- 主播列表
- 本机输出路径

因此它必须一直保持 git ignored。

## 录制文件策略

录制文件默认放到 `download/`，建议结构：

```text
download/
  streamer_id/
    streamer_id_title_20260521-120000.mkv
    streamer_id_title_20260521-120000.txt
    streamer_id_title_20260521-120000.comments.txt
    streamer_id_title_20260521-120000.comments.jsonl
  logs/
    streamer_id.log
```

视频、评论、日志都可能包含个人信息，默认不应进入 GitHub。
