# 项目进度与现状（2026-04-30）

本文整理本轮迭代中已完成的工作、当前默认行为、已知问题与下一步方向，便于后续继续开发和回溯。

## 1. 本轮已完成事项

### 1.1 结构整理（Monorepo）

- 已整理为双应用结构：
  - `apps/cli`
  - `apps/gui`
- 文档和脚本集中到根目录 `docs/`、`scripts/`。

### 1.2 GUI 主链路增强

- 多主播并发监控与录制主链路已打通。
- 新增底部运行日志面板（CMD 风格），用于观察操作状态和排错。
- 历史记录支持状态字段（如 `completed` / `interrupted`），并通过事件实时刷新前端。

### 1.3 暂停/开始逻辑修复

- 行级按钮从“切换（Toggle）”改为“显式设置（SetMonitoring）”，避免竞态导致的“点暂停后又恢复监听”。
- 全部开始/全部暂停沿用显式设置逻辑。

### 1.4 鉴权与直播信息获取

- Checker 已支持 OAuth 官方接口优先：
  - `GET /users/:id/current_live`
  - 使用返回的 `hls_url`
- 失败时回退 legacy 链路，保证兼容性。
- 设置页已加入 OAuth 获取教程（引导用户配置 `client_id`、`client_secret`、`redirect_uri`、授权 code、token 校验）。

### 1.5 录制链路与文件产物

- Recorder 目前为 `ffmpeg -c copy`（不转码）。
- 输出容器改为 `mkv`（原先为 `ts`），用于降低部分输入异常时的封装失败概率。
- 录制前会尝试将 HLS 变体调整到 `604.96`（若该档位可访问）；不可访问则回退原始链接。
- 录制时长采用多源计算：
  - 优先 `ffmpeg progress/out_time`
  - 必要时 `ffprobe` 回填
  - 最后兜底 wall-clock

### 1.6 日志降噪

- 前端对 `app-log` 做关键日志提取：
  - 保留：状态流转、开始/暂停/完成、失败信息、历史更新等
  - 过滤：高频 ffmpeg 噪声（Opening/Skip/progress/frame/fps/metadata 等）

## 2. 当前默认行为（截至 2026-04-30）

### 2.1 监控与录制

- 新增主播后默认立即进入监控状态。
- 已存在主播在应用启动后默认处于暂停状态（需手动开始或“全部开始”）。
- 直播中点击暂停会发送 `q` 给 ffmpeg，随后进程退出并写入历史（状态一般为 `interrupted`）。

### 2.2 鉴权模式

- 支持 `auto` / `oauth` / `cookie`。
- 推荐 `auto`：OAuth 优先，Cookie 作为补充。

### 2.3 录制输出

- 默认输出目录由设置页配置。
- 文件命名：`{streamer}_{title}_{timestamp}.mkv`

## 3. 与“录制君”对齐的关键点

- 已对齐其常见思路：优先抓可稳定播放的 HLS 分支，再进行 `copy` 录制。
- 对比日志发现，“录制君”并不总是录 1080p；很多场景会落在中档分支（如 `604.96`），稳定性更高。

## 4. 仍需关注的已知问题

- 个别主播在并发录制下仍可能出现首路断续、后路更稳定的现象。
- 某些场景下会出现输入流异常（如 NAL/分片异常）导致时长不连续，虽然已通过容器与链路策略缓解，但并非完全消除。
- 不同主播、不同时间段的 CDN 节点质量差异较大，稳定性存在波动。

## 5. 最近一次回归检查（本地）

- `apps/gui/frontend`: `npm run build` 通过。
